# 飞书日报规范（卡片 + 云文档双载体）

本文档是 GitHub 热门项目日报的唯一内容与视觉规范。定时任务生成日报前必须读取本文件；若自动化提示词与本文冲突，以本文为准。

> v2（2026-08-04 起生效，ADR-006）：由"单卡四段速览"升级为"单卡全深读 + 云文档全文"。历史 v1 规范（180–260 字符四段式）已废弃。

## 基本原则

- 使用飞书 Card 2.0，固定蓝色标题栏；标题不随模型自由发挥，只替换数量。
- 使用简体中文；仓库名必须链接到 GitHub 原仓库。
- **10 个项目全部完整深读，同等深度：不做分层、不做速览、不平均缩水。**
- 分析按"读者问题"组织，不按分析师维度：是什么（场景）→ 为什么火 → 比同类 → 关联 → 建议。
- **禁止裸分数**：热度分 / 技术分 / 风险分不得出现在卡片和文档正文，判断一律翻译成业务语言（如"热度低但含金量高""两周 +2600 star 持续走强"）。分数仅作内部参考。
- 卡片内不使用表格（云文档中允许），不粘贴大段 README 或源码，不展示 API Token 和原始 JSON。
- 无法确认的信息写"未确认"，不脑补；项目自述的关键数据（跑分、被引用等）未独立核实时必须标注来源为自述。

## 载体一：飞书卡片（当日唯一一张）

1. 标题：`GitHub 每日新项目｜10 个`
2. 元信息：北京时间日期、采集时间、候选仓库总数、推荐批次 ID、数据是否降级、"10 个全部完整深读"。
3. 云文档链接行：`📄 完整深度报告：[文档标题](url)`。
4. 今日观察：最多 3 条，每条一句话——共同技术方向、异常变化或值得警惕的信号。
5. 每日 10 个：严格按推荐接口排序，条目之间用分隔线，每条固定段式：
   - `排名 + 可点击仓库名 + 主语言 + star 数`（附一个关键动态数字：创建时长 / 周增 / fork 等）
   - `是什么｜` 用一个具体使用场景讲清楚它是什么。禁止抽象定位句（"多人 Agent 工作台"不算讲清楚，"公司 20 个员工每人有独立记忆和权限的 AI、频道里还有共用 AI"才算）。
   - `为什么火｜` 指出趋势拐点、出品方背书或触发事件，不能只说 star 涨得快。
   - `比同类｜` 点名至少一个同类或旧做法，说出差异。信息不足时可并入"是什么"，不硬凑。
   - `关联｜`（可选）与造梦次元业务或用户个人工具链的具体关联，行首标 ⭐；必须指向具体功能，无关联则整段省略。
   - `风险｜`（可选）值得警惕的信号（如商业导流、许可陷阱、内容敏感），行首标 ⚠️，写明证据。
   - `建议｜` 三选一：`✅ 值得花 30 分钟看` / `👀 收藏观察` / `➖ 了解即可`，各配一句理由。
6. 每条 250–500 中文字符。
7. 底部：灰字数据来源说明 + `📄 打开完整深度报告` 按钮（button 元素，open_url 指向当日云文档）。
8. 若 `exhausted=true` 或 `selectedCount<10`，标题保持不变，元信息明确写"当日达到热度门槛且未推荐的新项目仅 X/10"，不得用旧项目或低热度项目补位。

## 载体二：云文档全文报告（每日新建一篇）

- 创建方式：`lark-cli --profile work docs +create --doc-format markdown --title "GitHub 每日新项目深度报告｜YYYY-MM-DD" --content @<文件名>.md`
  - `@文件` 只接受**当前工作目录下的相对路径**，草稿文件先写到 cwd 再引用。
  - 创建成功后保存返回的 `url`，写入卡片链接行与底部按钮。
- 文档结构：元信息引用块 → 今日观察 → 10 个章节 → 数据来源尾注。
- 每个章节格式：
  - 标题：`## N. owner/repo —— 一句话定位`
  - 首行：仓库链接 + 数据行（主语言 / star / fork / 创建时长 / 许可证）
  - 五段完整版（各带小标题）：
    1. **这是什么（用场景讲）**
    2. **为什么是现在火**
    3. **跟同类比新在哪**
    4. **跟造梦次元的关系**（有才写；与用户个人工具链的关联也写在这段）
    5. **建议动作**
  - 章节末尾引用块写可信度：核验了哪些证据（README / 目录 / 代表文件 / 采集历史），哪些说法未确认。
- 云文档中允许表格与更长篇幅；卡片条目是文档章节的压缩版，两者结论必须一致。

## 业务关联口径（"关联｜"段是否成立的判断标准）

每个项目逐项过以下五类，命中才写，且必须指向具体功能。禁止"对 AI 平台有参考意义"式空话：

1. **AI 角色与对话**：人设、长期记忆、多轮对话、角色扮演类框架
2. **内容生成**：音乐 / 图片 / 视频 / 语音生成模型与工具链
3. **创作者与社区**：UGC 创作工具、内容分发、推荐、IP 运营
4. **工程基建**：推理降本、多租户隔离、内容安全、自动化测试
5. **同赛道动态**：情感陪伴、角色对话类开源产品与组件

另：与用户本人工具链（pi / Claude Code / 飞书等）直接相关的也算关联。

## 风险与降级表达

- 卡片与文档不展示风险分数；确有风险证据时在对应条目加 `风险｜⚠️` 并写明证据。
- README、代码或 GitHub 页面访问失败：对应条目写"未确认"，并在卡片元信息中汇总降级数量。
- 云文档创建失败：卡片照常发送，链接行改写"文档生成失败，今日深度内容以卡片为准"，计为降级。
- 即使发生部分降级，也要发送已有结果，不能让整份日报失败。

## 发送规则

- 使用 `feishu card send --to me --file <card.json>` 发送给用户本人；每日只发送一张卡片、创建一篇云文档。
- 发送成功后删除临时卡片文件与报告草稿文件（云文档本身保留）。
- 任务结果只保留：推荐批次 ID、项目数、卡片 message_id、云文档 url、是否耗尽、降级情况。

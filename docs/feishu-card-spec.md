# 飞书日报卡片规范

本文档是 GitHub 热门项目日报的唯一视觉与内容规范。定时任务生成卡片前必须读取本文件；若自动化提示词与本文冲突，以本文为准。

## 基本原则

- 使用飞书 Card 2.0，优先保证手机端快速浏览。
- 使用简体中文；仓库名称必须链接到 GitHub 原仓库。
- 不使用表格，不粘贴大段 README 或源码，不展示 API Token 和原始 JSON。
- 固定使用蓝色标题栏。标题不随模型自由发挥，只替换日期、页码和数量。
- 分数保留一位小数；缺失信息显示“未确认”，不猜测。

## 卡片结构

### 唯一卡片：GitHub 每日新项目｜10 个

1. 标题：`GitHub 每日新项目｜10 个`
2. 元信息：北京时间日期、采集时间、候选仓库总数、推荐批次 ID、数据是否降级。
3. 今日观察：最多 3 条，每条一句话，概括共同技术方向、异常变化或值得关注的趋势。
4. 每日 10 个：严格按每日推荐接口排序，每个仓库使用以下固定四段：
   - `排名 + 仓库链接 + 主要语言`
   - `定位｜` 一句话说明它解决什么问题、适合谁。
   - `亮点｜` 说明近期受关注的原因和最有价值的特点。
   - `代码｜` 基于实际目录和关键文件，说明一个具体实现机制或可复用工程思路。
   - `判断｜` 热度、技术、风险、置信度；有明显风险时补一句风险原因。
5. 每个仓库控制在 180–260 个中文字符；仓库之间使用分隔线。
6. 若接口返回 `exhausted=true`，标题仍保持不变，但元信息明确写“当日未推荐新项目仅 X/10”，不得用旧项目补位。

## 风险与降级表达

- 风险分低于 30：不加颜色词，仅展示分数。
- 风险分 30–59.9：标注“需留意”。
- 风险分不低于 60：标注“高风险”，并写明证据。
- README、代码或 GitHub 页面访问失败时，在对应仓库写“未确认”，并在第一张卡片元信息中汇总降级数量。
- 即使发生部分降级，也要发送已有结果，不能让整份日报失败。

## 发送规则

- 使用 `feishu card send --to me --file <card.json>` 发送给用户本人。
- 每日只发送一张深度卡片。
- 发送成功后删除临时 JSON 文件。
- 任务结果只保留推荐批次 ID、项目数、卡片 message_id 和降级情况。
